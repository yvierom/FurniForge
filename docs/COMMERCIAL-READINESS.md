# Commercial readiness notes

## Current position

FurniForge v0.4.2 is a developer preview. It has a tested Codex-assisted workflow, while the other three providers have setup instructions but no verified background integration. A repository and open source license do not by themselves provide a customer license, payment system or activation mechanism.

## What will make the product credible

1. **Show evidence:** capture an authorized reference photo beside the corresponding finished SketchUp model, plus one real screenshot of the workflow and a short screen recording. Label each example with input count, known dimensions and relevant manual refinement. Do not present unrelated or reconstructed examples as an automatic result.
2. **Prove repeatability:** test more furniture types, views, image quality and missing dimensions. Record failures, time, cost/usage, geometry editability and whether supplied measurements were met. Use findings to write accurate claims.
3. **Make onboarding predictable:** test the ZIP installation from a clean Windows account, document exact prerequisites and recovery, and minimize the number of manual steps before charging customers.
4. **Define the offer:** identify the intended buyer, licensing terms, price and usage limits, support/contact route, update policy, refund terms and how third-party AI charges work. These have not yet been implemented or decided.
5. **Review rights:** obtain permission for example photos and verify third-party font, library and assistant-logo terms before public distribution. The present notice retains third-party licensing details.
6. **Plan distribution:** consider a downloadable release, a public product site, or a marketplace listing. SketchUp Extension Warehouse requires developer application and review; verify current requirements before committing to that channel: https://help.sketchup.com/en/extension-warehouse/developing-extensions.
7. **Separate product and developer messages:** a customer-facing landing page should lead with the problem, a clear demonstration, compatibility, pricing and a call to action. The repository should support installation, releases, troubleshooting and technical detail.
